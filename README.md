# Планировщик производства

Пример распределения операций технологического процесса между сотрудниками.
План строится на Python с помощью Google OR-Tools CP-SAT. Веб-сервис работает
на FastAPI/Uvicorn, расчёт выполняет отдельный worker через очередь Redis Streams.
Изменения статуса приходят в браузер по SSE через Redis Pub/Sub.

## Требования

- Docker Engine;
- Docker Compose v2 (`docker compose`).

Проверить установленное окружение:

```bash
docker --version
docker compose version
```

## Веб-интерфейс (диаграмма Ганта)

Если сборка не может скачать зависимости из PyPI (`Network is unreachable`),
укажите доступный из Docker прокси в локальном файле `.env`. Например, для
Docker Desktop с прокси на `http.docker.internal:3128`:

```dotenv
BUILD_HTTP_PROXY=http://http.docker.internal:3128
BUILD_HTTPS_PROXY=http://http.docker.internal:3128
```

Без этих переменных сборка подключается напрямую. Файл `.env` исключён из Git
и контекста сборки; прокси передаётся только на этапе сборки.

Запустить веб-версию на порту `8096`:

```bash
docker compose up --build web
```

Открыть [http://localhost:8096](http://localhost:8096). В форме можно выбрать
дату планирования, количество изделий (до 30) и отфильтровать диаграмму по
бригаде (`Department`). Гант показывает отдельную строку для каждой бригады;
для каждой бригады отдельно рассчитывается выполнение всего заказа только
её сотрудниками. Worker считает department 1, затем department 2 и так далее.
Гант показывает полные сценарии на общей шкале времени, словно бригады
выполняли одинаковое задание параллельно. Сравниваются фактические даты
завершения; лучший найденный план выделяется. Одна бригада не выполняет две
операции одновременно.
Наведение на блок операции показывает исполнителя, оборудование,
эффективность, фактическую длительность и время выполнения. Под диаграммой
отображается дерево техпроцесса изделия: этапы → группы → операции. Этапы
и группы можно сворачивать; у операций показаны оборудование и
нормативное время на одно изделие. Данные передаются в поле `techProcess`
ответов состояния задания и SSE; фильтр подразделения влияет только на диаграмму.

При запуске `web` Compose также запускает Redis и worker. Задания, результаты
и снимки входных данных хранятся в Redis; включены AOF и том `redis-data`.
Интерфейс показывает состояния «В очереди», «Рассчитывается», «Завершено»
или причину ошибки для каждой бригады. Горизонт задаётся в форме (по умолчанию
14 календарных дней): следующие операции могут переноситься на рабочие дни.
Каждая операция целиком должна помещаться в одну смену; ночи и выходные исключены.
Если бригада не может выполнить заказ, её ошибка остаётся в сравнении,
а расчёт остальных бригад продолжается.

API (описание также доступно на `/docs`):

- `POST /api/jobs` с JSON `{"count":1,"planning_day":"2026-10-05","horizon_days":14,"compare_departments":true}` —
  создаёт задание, возвращает HTTP 202 и ссылки `eventsUrl`, `resultUrl`;
- `GET /api/jobs` — до 100 последних заданий;
- `GET /api/jobs/{id}` — состояние, техпроцесс и результат;
- `GET /api/jobs/{id}/events` — SSE-события `job` через Redis Pub/Sub.

Синхронный `GET /api/plan` заменён на `POST /api/jobs`. При новом SSE-подключении
отдаётся актуальное сохранённое состояние; после конечного статуса поток
закрывается. Подробности очереди и восстановления — в
[описании заданий](docs/tasks/task.md).

Для локального запуска без Docker установите зависимости из `requirements.txt`,
запустите Redis и задайте `REDIS_URL` (по умолчанию `redis://localhost:6379/0`).
Запустите `python3 -m planner.worker` и `python3 -m planner.web` в отдельных
терминалах. Redis-тесты включаются, если задан `REDIS_URL`; используйте отдельную
тестовую БД, например `/1`. В Compose это уже настроено.

## Консольный запуск

Собрать образ и запустить планировщик:

```bash
docker compose up --build planner
```

Сервис является одноразовой задачей: он создаёт тестовые данные, рассчитывает
производственный план, выводит назначения в консоль и завершается.

В успешном выводе должны присутствовать секции:

```text
TEST DATA
TECH PROCESS
PRODUCTION PLAN
ASSIGNMENTS BY DEPARTMENT
```

Статус плана должен быть `OPTIMAL` или `FEASIBLE`. Для каждой операции выводятся
время начала и окончания, этап, сотрудник, подразделение, эффективность и
фактическая длительность.

Повторный запуск без пересборки образа:

```bash
docker compose run --rm planner
```

## Проверка OR-Tools

Проверить импорт библиотеки и установленную версию:

```bash
docker compose run --rm planner \
  python -c "import ortools; print(ortools.__version__)"
```

Ожидаемая версия:

```text
9.15.6755
```

## Тесты

Запустить все доменные и интеграционные тесты:

```bash
docker compose --profile test run --build --rm tests
```

В конце успешного запуска будет выведено:

```text
OK
```

Запустить только тесты генератора и доменной модели:

```bash
docker compose --profile test run --rm tests \
  python -m unittest discover -s tests \
  -p 'test_domain_and_test_data.py' -v
```

Запустить только интеграционные тесты CP-SAT:

```bash
docker compose --profile test run --rm tests \
  python -m unittest discover -s tests \
  -p 'test_cp_sat_planner.py' -v
```

## Проверка Docker Compose

Проверить итоговую конфигурацию без запуска контейнеров:

```bash
docker compose config --quiet
```

Команда завершается без вывода и с кодом `0`, если конфигурация корректна.

## Остановка и очистка

Удалить созданные контейнеры и сеть проекта:

```bash
docker compose down --remove-orphans
```

Удалить также локальный образ планировщика:

```bash
docker compose down --remove-orphans --rmi local
```

## Структура

```text
planner/
├── domain/          # Доменные сущности и бизнес-правила
├── application/     # Сценарий планирования и порт оптимизатора
├── infrastructure/  # CP-SAT и генератор тестовых данных
└── main.py          # Точка входа
tests/               # Доменные и интеграционные тесты
```

Описание правил планирования находится в
[`docs/planner/readme.md`](docs/planner/readme.md).
